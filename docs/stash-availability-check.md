# On-demand Stash availability

**Check Stash availability** is available in the acquisition row actions (inline when space permits, otherwise overflow) and scene Lifecycle actions. It makes a fresh read-only check, without needing a Whisparr entry or a Portal request. Nothing is prefetched per row.

Results distinguish Available in Stash, No match found, Couldn’t verify and Setup needed. Confirmed copies link directly to their Stash scene using the configured browser address. Exact catalog links use the instance's provider namespace; the existing source-identity fallback requires matching URL, studio and duration. Metadata-only records without listed files do not count as available. Explicit checks reject partial/malformed responses rather than interpreting them as absence. A file can still be imported but unidentified; a negative result explains identification and is not a filesystem search.

The check does not create/change tracking, update acquisition status, start Whisparr/Hydra searches, scan, identify, edit metadata or delete media. Existing automatic library synchronization remains responsible for Portal's cached lifecycle. The dialog offers Check again and the ordinary Stash library link. Provider errors leave availability unknown. No schema/settings migration is needed.

**Search Stash for all** sits in the Acquisition header beside Refresh, outside the selection/bulk toolbar. It gathers all currently tracked acquisitions across all pages, ignoring the current filters and selection, then checks them sequentially with visible progress and per-scene results. Results paginate in groups of 50 and preserve direct links to matched copies. Stop checking and Close cancel remaining client requests; no queued checks are dispatched after cancellation. A provider lookup already received by the server may finish. Nothing is prefetched, and a changed/incomplete acquisition snapshot aborts before Stash checks begin. Unknown responses never count as negative matches.

The source-identity fallback also supports manually acquired scenes with no scene-level catalog IDs. It still requires an authoritative matching source URL, a provider-qualified matching studio ID, and a listed file with positive size and matching duration. Title/filename similarity alone never establishes availability. This does not write catalog associations to Stash.

Confirmed AVAILABLE results sort first across the entire result set before pagination, keeping the original order within the found and remaining groups. Found rows have a direct Delete request action, and Delete found requests reviews all confirmed copies together without selection. The same dialog uses Items / Impact tabs and explicitly confirms removal of the Portal requests **and their exact Whisparr entries when present**. Stash records/copies, media files, folders and download-client jobs are kept. This action always uses Whisparr `deleteFiles=false` and `addImportExclusion=false`; it does not offer file deletion.

Before confirmation, each eligible scene receives a signed, five-minute entry-only preview. The full Whisparr scene list is read to establish an exact, unique StashDB match or confirmed absence. Active commands/transfers, duplicate matches, unavailable evidence and other active Portal actions block that item. Blocked items remain in the review and are skipped. Missing Whisparr entries are shown as Portal-only cleanup; a failed lookup never implies absence. Unconfigured Whisparr or a non-StashDB catalog cannot be verified for this action and are blocked. These checks are separate from Stash availability and do not alter either service.

Confirmed targets execute sequentially with a stable, distinct operation key and frozen preview token per scene. The server revalidates connection, provider identity, expiry, exact entry and idle state before dispatch. If an entry changed, appeared or vanished since review, a new review is required. Native deletion is never retried automatically. Acknowledged entry deletion is confirmed by both an individual lookup and the complete scene list before the Portal request is dismissed. A missing entry results in Portal-only dismissal. History is retained under Delete Whisparr entry (keep files).

Known removals stay marked Removed from Portal with Stash links retained. Uncertain or malformed responses stop later targets, preserve original keys/tokens for explicit replay, and keep unknown requests unmarked. Item History's Check outcome verifies an uncertain entry deletion by reads only and can finish the dismissal after absence is confirmed. Navigation cancels later client requests; an already-received server action may finish. Cancellation before confirmation changes nothing. The acquisition list refreshes after attempted confirmed cleanup.

A server-confirmed failure before dispatch stops remaining cleanup, shows its reason and allows a fresh review with new operation keys. Unknown outcomes retain the original review for recovery.
